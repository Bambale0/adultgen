# Архитектура AdultGen MVP

## Идея продукта

AdultGen — Telegram-first платформа для создания AI-фото и AI-видео. Пользователь создаёт проект, добавляет сцены, загружает аватар и референсы, запускает генерацию и получает результат в Telegram-чате. Mini App используется как красивый и удобный интерфейс для проектов, ленты, профиля, баланса, партнёрского кабинета и настроек.

Платформа рассчитана на adult-сегмент, поэтому архитектура сразу учитывает:

- high-risk платежи;
- жалобы и модерацию;
- immutable webhook logging;
- 18+ gate;
- Telegram-боты-зеркала;
- сохранность баланса при замене бота;
- ручную публикацию результата;
- ограниченное хранение временного медиа.

## Главный архитектурный принцип

Telegram-бот не владеет пользователями, балансами, платежами, проектами и публикациями. Бот — только сменяемый канал доступа.

```text
Telegram Bot A ─┐
Telegram Bot B ─┼──▶ Telegram Gateway ───▶ Core API
Telegram Bot C ─┘                              │
Mini App ──────────────────────────────────────┘
                                                │
                    ┌───────────────────────────┼───────────────────────────┐
                    ▼                           ▼                           ▼
              PostgreSQL                      Redis                  S3 storage
```

Если бота заблокируют, заказчик подключает новое зеркало к тому же backend, а пользователи сохраняют:

- баланс;
- подписку;
- проекты;
- опубликованные работы;
- публичный профиль;
- партнёрский кабинет.

Канонический ключ пользователя:

```sql
UNIQUE (telegram_user_id)
```

Нельзя делать пользователя уникальным по паре `(bot_id, telegram_user_id)`.

## Runtime-приложения

На старте это модульный монолит в одном репозитории, но запущенный несколькими процессами.

```text
apps/
├── core_api                 # пользователи, кошелёк, проекты, лента, админка
├── mini_app_api             # auth/initData и API для Mini App
├── telegram_gateway         # webhooks нескольких Telegram-ботов
├── generation_worker        # задачи Kie/Seedream/Seedance
├── composition_worker       # FFmpeg-сборка многосценовых роликов
├── billing_gateway          # checkout page и платёжные адаптеры
├── payment_webhook_ingress  # raw immutable webhook capture
├── payment_worker           # идемпотентная обработка платежей
├── media_worker             # TTL, копирование публикаций, blur/preview
├── broadcast_worker         # сегментированные рассылки
├── scheduler                # cleanup, подписки, выплаты
└── admin_api                # админские действия и модерация
```

## Telegram bot

Бот отвечает за:

- `/start` и mirror-aware onboarding;
- открытие Mini App;
- приём файлов, если пользователь работает через чат;
- отправку результата генерации;
- inline-кнопки после результата;
- базовый баланс и оплату;
- поддержку;
- админские команды первого уровня.

После генерации бот отправляет оригинальный файл:

```text
✅ Генерация завершена

[Опубликовать]
[Повторить]
[Продолжить сцену]
[Открыть проект]
```

Mini App не обязан иметь отдельный центр уведомлений: актуальное состояние подтягивается через API.

Дополнительные разделы:

- поддержка;
- настройки 18+;
- админский контур для владельца.

## Генерация

Основной MVP flow:

```text
Создать проект
      ↓
Создать сцену вручную
      ↓
Добавить описание
      ↓
Выбрать аватар
      ↓
Добавить основной кадр
      ↓
Добавить референсы
      ↓
Выбрать режим модели
      ↓
Посчитать цену
      ↓
Зарезервировать кредиты
      ↓
Отправить задачу в Kie
      ↓
Получить callback
      ↓
Сохранить результат и last frame
      ↓
Отправить файл в Telegram
      ↓
Опубликовать вручную или удалить по TTL
```

AI-режиссёр не обязателен. Он вызывается вручную кнопкой, например:

```text
✨ Помочь со сценой
```

Без AI-режиссёра система всё равно должна работать: формы, prompt compiler, reference mapping и provider payload builder достаточно для запуска.

## Проекты и сцены

Пользователь сам создаёт сцены. Система не навязывает автоматическую раскадровку.

```text
Project
├── Scene 1
├── Scene 2
└── Scene 3
```

Для многосценового режима в MVP фиксируется строгая связность:

- аватар;
- лицо/референсы;
- одежда;
- локация;
- свет;
- предметы;
- направление движения;
- last frame предыдущей сцены.

Режиссёрская связность, ось камеры и сложная монтажная логика — следующий этап.

## Биллинг

Фото считается фиксированной ценой за операцию:

```text
Seedream 5 Pro text-to-image  -> fixed image price
Seedream 5 Pro image-to-image -> fixed edit price
```

Видео считается за секунду:

```text
стоимость = duration_seconds × video_second_price
```

Кошелёк строится через append-only ledger:

```text
payment_credit
subscription_credit
bonus_credit
generation_reserve
generation_charge
generation_release
refund
admin_adjustment
chargeback
```

Нельзя делать источником истины изменяемое поле `users.balance`.

## Платежи

Провайдеры подключаются через абстракцию:

```text
PaymentProvider
├── SharPayProvider
└── CrocoPayProvider
```

Платёжный flow:

```text
Пользователь выбирает пакет
      ↓
Core API создаёт PaymentOrder
      ↓
Billing Gateway создаёт checkout
      ↓
Пользователь платит
      ↓
Webhook сохраняется как raw immutable record
      ↓
Payment Worker проверяет подпись/статус
      ↓
Ledger начисляет кредиты
      ↓
Telegram отправляет уведомление
```

Платёжные webhook должны сохраняться до парсинга и бизнес-логики.

## Хранение медиа

- Временные результаты генерации: 24 часа.
- Пользователь всё равно получает оригинал в Telegram-чате.
- Постоянно хранятся только публикации в профиле и общей ленте.
- Удалённые аватары и референсы должны физически удаляться.
- Финансовый ledger, raw webhook и audit остаются.

## Лента

В MVP есть одна общая лента:

- без подписок;
- без комментариев;
- только ручной свайп;
- likes;
- saves в коллекцию;
- remix со своими аватарами/референсами;
- профиль автора;
- жалобы;
- admin blur/hide/boost/delete.

Explicit-контент доступен после 18+ gate. Blur может быть включён автором или принудительно администратором.

## Партнёрская программа

Модель:

```text
20% с первой успешной оплаты
5% со следующих платежей в течение 90 дней
```

Вознаграждение начисляется на денежный партнёрский баланс. Вывод — ручной запрос, админ переводит деньги вручную и отмечает выплату.

## Админка

В MVP один superadmin, но действия внутри кода уже должны иметь permissions.

Разделы:

- пользователи;
- балансы и ledger;
- платежи;
- raw webhook logs;
- генерации;
- модели и цены;
- подписки;
- промокоды;
- рефералы;
- партнёрские выплаты;
- публикации и лента;
- жалобы;
- рассылки;
- боты-зеркала;
- настройки хранения;
- аудит.

Каждое опасное действие требует reason и запись в `admin_audit_events`.
