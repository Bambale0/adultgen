# Решение о полном сбросе фронтенда

Дата: 2026-08-07
Статус: принято

## Решение

Полностью удалить все существующие реализации фронтенда и вернуть AdultGen к backend-first базе.

Удалены:

- `apps/mini_app`;
- `apps/web_app`;
- связанные UI-тесты, сборочные job, Docker-образы, SPA-конфигурации Nginx, readiness-отчёты, audit-roadmap и документы прошлых pivot.

Удалённый код нельзя использовать как основу нового клиента.

## Причина

В репозитории одновременно накопились два конкурирующих направления фронтенда, дублирующиеся production-конфигурации, монолитные компоненты, слои CSS-переопределений и тесты, проверявшие наличие строк в исходниках вместо поведения продукта. Дальнейший косметический ремонт сохранил бы неверную архитектуру и увеличил стоимость переделки.

## Что остаётся

- Core API и доменная модель;
- Telegram gateway и его контракты;
- API аутентификации и 18+ consent;
- API генерации, медиа, профиля, коллекций, публикаций, модерации, биллинга, кошелька, подписок и админки;
- backend-тесты;
- production deployment только для API.

## Условия начала нового фронтенда

До начала реализации должны быть утверждены:

1. Основная поверхность продукта: Telegram Mini App, публичный web, admin или осознанная multi-client схема.
2. Карта маршрутов и критические пользовательские сценарии.
3. State machine для auth, Telegram init-data, сессии и 18+ consent.
4. Состояния генерации, ошибки, retry и доставка результата.
5. Flow загрузки, профиля, коллекций, публикации, ленты, жалоб и модерации.
6. UX биллинга и подписок с точными backend-контрактами.
7. Дизайн-токены, типографика, сетка, компоненты, адаптивность и accessibility.
8. Типизированный API-клиент и стратегия server state.
9. План unit, integration, visual regression и critical-path E2E тестов.
10. Схема деплоя и наблюдаемость.

## Правила следующей реализации

- Одновременно разрабатывается только одно цельное направление фронтенда.
- Сначала создаются app shell, навигация, state model и API adapters.
- Feature-модули не должны зависеть напрямую от transport и Telegram globals.
- Запрещены монолитные page-компоненты и каскады CSS override.
- В production manifest нельзя использовать версии зависимостей `latest`.
- Lockfile обязателен.
- CI добавляется вместе со scaffold, а не после разработки.
- Готовность подтверждается поведением и E2E, а не поиском строк в исходниках.

## Текущее поведение runtime

Production gateway продолжает отдавать `/api/*` и `/healthz`. Все остальные web-пути отвечают:

```json
{"detail":"frontend_not_installed"}
```
